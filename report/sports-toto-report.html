4. 기술 구성

프런트엔드

  • Next.js 16.1.7 (App Router, Turbopack)
  • React 19.2.3, TypeScript strict
  • Tailwind v4, Zustand (슬립/계정 상태)

백엔드와 데이터

  • Prisma 5.22 + PostgreSQL (enum 사용)
  • NextAuth v5 beta.31, bcryptjs 12 rounds
  • 모든 금액은 정수 sen (1 MYR = 100 sen)

핵심 설계 포인트

  • 서버 재계산: 클라이언트가 보낸 금액·배수는 신뢰하지 않고 서버가 다시 계산합니다.
  • 원장 무결성: 모든 잔액 변경은 mutateWallet() 한 경로로, 잔액 변경과 Transaction 기록이 같은 트랜잭션입니다.
  • 중복 방지: Bet.idempotencyKey unique 로 같은 요청 재전송 시 재차감하지 않습니다.
  • 매칭 로직 재사용: Phase 5 정산에서 같은 matching.ts 를 사용할 수 있게 분리했습니다.

9. 다음에 해야 할 일

Vercel 이 계속 실패하는 이유

최근 두 번의 빌드 로그 모두 Commit: 66794f6 이고 prisma db push --skip-generate 옛 스크립트가 실행되었으며, DATABASE_URL 이 설정되어 있지 않았습니다. 즉 가드 fix 가 Zimbabwe 에 아직 없고 Postgres 도 연결되지 않은 상태입니다.

Vercel 대시보드에서 (가장 빠른 길)

  • Storage → Create Database → Postgres 생성 후 Zimbabwe 프로젝트에 연결 (DATABASE_URL 자동 주입)
  • Environment Variables 에 AUTH_SECRET (openssl rand -base64 32), NEXTAUTH_URL 추가
  • Redeploy → 성공 후 로컬에서 npm run db:seed 한 번 실행

선택: 가드 fix 를 Zimbabwe 에 반영 (로컬 터미널)

git clone https://github.com/khi3628-dev/Zimbabwe.git
cd Zimbabwe
git pull --rebase https://github.com/khi3628-dev/mu8ig.git sports-toto-only
git push origin main
주의 사항
  • 이 대화 중 로컬 .env 의 AUTH_SECRET 값이 화면에 노출되었습니다. 배포용 값은 반드시 새로 생성해서 쓰세요.
  • /api/wallet/dev-topup 은 production 에서 403 이라 Vercel 배포본에서는 잔액 충전이 안 됩니다. Phase 5 의 Stripe 테스트 입금이 들어오기 전까지 배포본에서는 베팅 체험이 제한됩니다.
  • 실제 서비스로 운영하려면 말레이시아 라이선스가 필요하며 이 코드는 그 용도가 아닙니다.
