# 에코샤드 플레이 가능 프로토타입

`EchoShard_Mobile_MOBA_GDD_KO.docx`의 15분 경기 구조를 **실제로 플레이하고 측정하기 위한** 프로토타입입니다.
투자용 기획서를 구현물로 옮긴 것이 아니라, 기획서가 주장하는 단 하나의 가설을 검증하기 위한 도구입니다.

> 5:00 천정 고래 → 8:00 세계 접힘 → 10:00 심층 고래 → 14:00 과부하가
> 실제로 긴장과 결전을 만들고, 경기를 13~15분에 끝내는가?

## 실행

```bash
npm install
npm run dev
```

- `http://localhost:3000/echoshard` — 1인 플레이(봇 9기)
- `http://localhost:3000/echoshard/lab` — 배치 시뮬레이션 실험실

조작: `WASD` 이동, 마우스 조준, `Q` `F` `E` `R` 스킬(`F`가 W 스킬), `X` 대상 우선순위, 클릭 수동 지정.
모바일은 화면 좌측 드래그로 이동, 우측 버튼으로 스킬.

명령줄에서 대량 측정:

```bash
npx esbuild lib/echoshard/smoke.ts --bundle --platform=node --format=esm --outfile=/tmp/smoke.mjs
node /tmp/smoke.mjs 24 --ab     # 접힘 켬/끔 A/B 비교
```

## 범위

기획서 전체가 아니라 "경기감"에 필요한 것만 구현했습니다.

| 구현함 | 구현하지 않음 |
| --- | --- |
| 20Hz 고정 틱 전투, 결정적 시드 | 온라인 대전·전용 서버·매치메이킹 |
| 직조분지(3라인 + 정글 + 강), 8:00 세계 접힘 | 랭크·MMR·드래프트·밴 |
| 미니언 웨이브·포탑·직조핵·과부하 | 상점 UI (추천 빌드 자동 구매로 대체) |
| 중립 오브젝트 4종과 버프 | 스킨·배틀패스·수익화 |
| 영웅 5종 P/Q/W/E/R 전체 | 나머지 영웅 7종 |
| 안개·부시·시야 차단 | 정찰핵 설치, 위장 |
| 봇 9기, 배치 시뮬레이션 | 관전·리플레이·음성 |

영웅 5종은 부록 F가 지정한 4종(가온·이도·연화·사엘)에 **네루**를 더했습니다.
부록 F 조합에는 추적자(정글)가 없어 5레인 5v5를 구성할 수 없습니다. 5종이면 5역할이 정확히 채워집니다.

양 팀 모두 같은 5영웅을 씁니다. 영웅 밸런스를 변수에서 제거해야 진영 승률을 측정할 수 있기 때문입니다.

## 파일 구조

```
lib/echoshard/
  config.ts      GDD 수치 이식본. [가정] 주석이 붙은 값은 문서에 없어 채운 것
  types.ts       공통 타입
  map.ts         직조분지 생성, 접힘, A* 경로 탐색
  sim.ts         20Hz 틱 시뮬레이션 (GDD 4.1 전투 순서 그대로)
  abilities.ts   영웅 5종 스킬
  ai.ts          봇 9기
  headless.ts    배치 시뮬레이션 + 문서 기준 대조
  render.ts      캔버스 렌더러
app/echoshard/   플레이 화면 / 실험실
```

시뮬레이션 코어는 DOM에 의존하지 않습니다. 그래서 같은 코드가 화면 없이 브라우저·노드에서 대량 실행됩니다.
사람 10명 없이 경기 길이를 측정할 수 있는 유일한 경로입니다.

## 구현하면서 문서에서 발견한 것

### 1. 표 21과 부록 C가 서로 모순된다

- 표 21: "직조핵은 내곽 포탑 **하나 이상 파괴 시** 공격 가능"
- 부록 C 불변식: "직조핵은 연결된 내곽 포탑이 **하나 이상 생존하면** 피해를 받지 않는다"(= 전부 파괴 필요)

경기 길이가 완전히 달라지는 차이입니다. 15분 목표에 맞는 표 21 해석을 기본값으로 두고
`CoreShieldMode` 플래그로 둘 다 실험할 수 있게 남겼습니다. 문서에서 한쪽을 지워야 합니다.

### 2. 리스폰 시간표가 없다

문서에는 재결속 시간 규정이 없습니다. 사소한 누락이 아니라 **경기 종결 속도를 직접 결정하는 값**입니다.
짧게 잡았더니 한타를 이겨도 밀지 못해 경기가 30분을 넘겼습니다.

### 3. 회전 대칭 맵만으로는 진영 승률 49~51%가 보장되지 않는다

문서는 맵의 회전 대칭을 요구하지만 오브젝트 좌표는 규정하지 않습니다.
강 위의 모든 점은 두 직조핵에서 유클리드 거리가 같지만, **정글 통로 접근성이 다릅니다.**

반복 생성되는 천정 고래를 한쪽에 고정했더니 진영 승률이 25% / 75%로 갈렸고,
같은 시드 16경기에서 두 고래 위치를 맞바꾸자 승률이 그대로 뒤집혔습니다(25% → 56%).

→ 반복 오브젝트는 교대 생성하거나 중앙에 두어야 합니다. 문서에 이 제약을 명시해야 합니다.

### 4. 틱 파이프라인이 진영 승률을 만든다

유닛을 순서대로 이동시키면 뒤 순서 유닛이 앞 유닛의 갱신된 위치를 보고 반응합니다.
유닛 id는 청 팀이 먼저 발급되므로, 이 순차 처리가 적 팀에 매 틱 50ms짜리 반응 우위를 줬습니다.
같은 스냅샷에서 이동을 계산하도록 고치자 청 승률 25% → 35%, 8분 골드차 1154 → 458로 줄었습니다.

문서 4.1은 **피해** 적용 순서만 규정합니다(sourceEntityId 오름차순).
**이동** 역시 같은 스냅샷에서 계산해야 한다는 규정이 필요합니다.

### 5. 부록 F의 선행 영웅 4종으로는 5v5를 못 만든다

가온·이도·연화·사엘에는 정글러가 없습니다. 첫 플레이테스트 조합에 추적자 1종이 필요합니다.

### 6. 세계 접힘의 위치가 규정돼 있지 않다 — 그리고 그게 전부를 결정한다

문서 3.4는 "외곽 정글 벽 **4곳**이 바닥으로 내려간다"고만 씁니다. 어느 4곳인지는 없습니다.
그래서 제가 임의로 골랐고, 골라 놓고 측정했더니 **아무 일도 일어나지 않았습니다**(아래 결과 참조).

접힘은 이 게임의 유일한 오리지널 규칙입니다. 그 규칙의 효과가 전적으로 "어느 벽을 여는가"에 달려 있는데
문서에는 그 좌표가 없습니다. 기획서에서 가장 먼저 채워야 할 칸입니다.

## 측정 결과

`node /tmp/smoke.mjs 24 --ab` — 접힘 켬 24경기 / 끔 24경기, 같은 시드 집합.

| 지표 | 접힘 켬 | 접힘 끔 | 문서 기준 |
| --- | --- | --- | --- |
| 경기 길이 P50 | 23:18 | 23:16 | 13:00~15:00 · **미달** |
| 경기 길이 P90 | 28:11 | 29:53 | ≤ 19:00 · **미달** |
| 13~15분 적중률 | 0.0% | 0.0% | — |
| 청 승률 | 25.0% | 50.0% | 49~51% |
| 8분 열세팀 역전률 | 29.2% | 70.8% | ≥ 15% · 통과 |
| 접힘 구역 교전(직후 60초) | 0 | 0 | — |

### 읽는 법

**1. 접힘은 경기 길이를 2초 바꿨습니다.** 48경기에서 P50 차이가 23:18 vs 23:16입니다.
문서가 접힘에 부여한 역할("교착 제거", "8분 추격 창구")이 현재 구현에서는 측정되지 않습니다.
단, 위 발견 6번대로 벽 위치는 제가 임의로 정한 것입니다. 이 숫자는 **"접힘이 나쁘다"가 아니라
"접힘은 벽 위치를 정하기 전까지 아무것도 아니다"** 로 읽어야 합니다.

**2. 접힘 구역 교전이 양쪽 다 0입니다.** 봇들이 그 근처에서 아예 싸우지 않습니다.
제가 연 4곳이 실제 교전 동선에서 벗어나 있다는 뜻입니다. 벽 위치를 정할 때의 기준이 여기서 나옵니다:
**접힘은 사람들이 이미 싸우는 곳으로 가는 길을 열어야 합니다.**

**3. 경기가 23분입니다.** 목표의 1.5배입니다. 다만 원인이 설계인지 봇 실력인지 **아직 분리되지 않았습니다.**
봇은 한타를 이긴 뒤 압박으로 전환하는 판단이 느리고 포탑 철거 우선순위가 단순합니다.
이 숫자를 "기획서가 틀렸다"는 근거로 쓰면 안 됩니다.
지금 이 도구가 답할 수 있는 것은 "봇 수준에서 이 규칙들이 어떤 경기를 만드는가"까지입니다.

**4. 청 승률 25% vs 50%는 표본이 부족합니다.** 24경기에서 6승과 12승의 차이는 통계적으로 결정적이지 않습니다.
진영 승률 49~51%를 주장하려면 문서 기준대로 10,000경기가 필요합니다. 현재 한 경기에 약 16초가 걸립니다.

측정은 실험실 화면(`/echoshard/lab`)에서 언제든 다시 뽑을 수 있습니다.

## 다음에 할 일

우선순위 순입니다.

1. **직접 플레이한다.** 숫자보다 이게 먼저입니다. 8:00에 벽이 내려갈 때 하던 판단이 바뀌는지,
   아니면 그냥 배경이 바뀌는지는 손으로만 알 수 있습니다.
2. **접힘 벽 4곳을 제대로 정한다.** `lib/echoshard/map.ts`의 `FOLD_BLUE` 두 사각형만 바꾸면 됩니다
   (나머지 2곳은 회전 대칭으로 자동 생성). 기준: 이미 교전이 벌어지는 곳으로 가는 우회로를 끊을 것.
   바꾼 뒤 실험실에서 A/B를 다시 돌리면 접힘이 게임을 바꾸는지 즉시 나옵니다.
3. **봇의 압박 판단을 개선하고 경기 길이를 재측정한다.** 설계 문제와 AI 문제를 분리해야
   23분이라는 숫자에 의미가 생깁니다.
4. 접힘 시각을 6:00 / 8:00 / 10:00으로 바꿔가며 경기 길이 곡선을 뽑는다.
5. 영웅을 3종 더 추가해 조합 다양성이 경기 길이에 주는 영향을 본다.
